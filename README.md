# المرشد الأكاديمي الذكي

> مساعد يجيب الطلبة عن لوائح الجامعة وخطتهم الدراسية بالفصحى والعامية، مع رقم المادة من اللائحة ورمز المادة الدراسية، ويخفف الأسئلة المتكررة عن الدوائر الأكاديمية.

**المشكلة:** الطلبة يضيعون بين اللوائح والخطط الدراسية والمتطلبات السابقة، وتتكرر الأسئلة نفسها على الدوائر الأكاديمية والمرشدين كل فصل، خصوصًا في فترات التسجيل والانسحاب.

**لماذا RAG وليس نموذجًا لغويًا وحده؟** النموذج العام لا يعرف لوائح جامعتنا، وسيخترع أرقامًا معقولة الشكل لكنها خاطئة (مثل حد الغياب أو أسبوع الانسحاب). RAG يجعل كل إجابة مستندة إلى نص اللائحة الرسمي مع رقم المادة، فيستطيع الطالب التحقق بنفسه.

## التشغيل السريع

```bash
python -m venv .venv && source .venv/bin/activate   # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env            # ضع مفتاح API و ADMIN_TOKEN

python scripts/ingest.py        # بناء الفهرس من data/docs
python scripts/ask.py "شو لازم آخذ قبل تعلم الآلة؟" --debug
uvicorn app:app --reload        # الطالب: http://localhost:8000   الإدارة: http://localhost:8000/admin
```

> ⚠️ البيانات في `data/` تجريبية لجامعة وهمية. راجعوا `REAL_DATA.md` لاستبدالها بوثائق جامعتكم.

## المعمارية

```
لائحة الدراسة + دليل الطالب + الخطة الدراسية (PDF/MD)
        └─► تقطيع حسب المادة والقسم والجدول ─► embeddings + BM25 ─► الفهرس

courses.csv ─► رسم بياني للمتطلبات السابقة (يُحسب بالكود، دقة 100%)

سؤال الطالب ─► إعادة صياغة (عامية ← فصحى، أسئلة المتابعة)
            ├─► بحث هجين في الوثائق (RRF)
            └─► التقاط المواد المذكورة ─► سلسلة المتطلبات / المواد المتاحة للتسجيل
            ─► عتبة رفض ─► توليد مؤرَّض ─► إجابة + [n] + "المادة 9" أو "CS201"
                                                   └─► سجل مجهول الهوية ─► لوحة الإدارة
```

| الملف | المسؤولية |
|---|---|
| `rag/chunking.py` | تقطيع حسب البنية: كل مادة من اللائحة قطعة مستقلة مع رقمها، والجداول تُقسم صفوفًا مع تكرار رأس الجدول |
| `rag/courses.py` | الخطة الدراسية كرسم بياني: سلسلة المتطلبات الكاملة، والمواد التي تفتحها المادة، والمواد المتاحة للتسجيل |
| `rag/index.py` | بحث هجين (دلالي + BM25) مدموج بـ RRF، وإعادة ترتيب اختيارية، وتصفية بالوثيقة |
| `rag/pipeline.py` | برومبت المرشد، إعادة الصياغة، دمج البيانات المنظَّمة مع النصوص، الرفض، والمصادر |
| `rag/analytics.py` | سجل الأسئلة دون هوية، وتجميع الأسئلة المتشابهة بالمعنى، والثغرات في الوثائق |
| `rag/arabic.py` | تنظيف العربية وتوحيد الحروف وتصحيح ترتيب الكلمات المعكوس في PDF |
| `app.py` | API: `/api/ask` و`/api/stats` و`/api/upload`، وصفحتا الطالب والإدارة |
| `scripts/evaluate.py` | Hit@k وPrecision@k وMRR ودقة الرفض وFaithfulness والتكلفة |

### قرارات التصميم ولماذا

- **التقطيع حسب مادة اللائحة لا حسب عدد الأحرف:** كل مادة وحدة معنى مستقلة، وعنوانها ("المادة (11): الإنذار الأكاديمي") يُضاف لكل قطعة منها فيطابق أسئلة الطلبة مباشرة، ورقمها يظهر في الاقتباس.
- **الجداول صفوف مع رأسها:** صف "CS201 | هياكل البيانات | 3 | CS102" بلا رأس الجدول لا يُفهم.
- **المتطلبات السابقة بالكود لا بالبحث:** سلسلة تعلم الآلة تمر بخمس مواد في أربعة فصول مختلفة. البحث الدلالي يجد حلقة أو اثنتين، والرسم البياني يجدها كلها دائمًا. النتيجة تدخل السياق كمقطع يُقتبس كأي مصدر.
- **أسماء الطلبة الدارجة للمواد:** عمود `aliases` يربط "داتا ستركتشر" و"كالكولس" و"ماشين ليرنينج" بالمادة الصحيحة.
- **الرفض على مستويين:** عتبة تشابه قبل استدعاء النموذج، ثم جملة رفض ثابتة في البرومبت. سؤال مثل "كم رسوم الساعة؟" خطير بالذات لأن اللائحة تذكر الرسوم دون مبلغ، والنموذج يجب أن يرفض بدل أن يخمّن.
- **لا قرارات نيابة عن الجامعة:** في الأعذار والاستثناءات والتظلمات يشرح ما تقوله اللائحة ويوجّه للجهة المختصة.

## التقييم

```bash
python scripts/evaluate.py --retrieval-only   # سريع ومجاني
python scripts/evaluate.py --judge            # المسار الكامل + حكم آلي على الأمانة للمصادر
```

## لوحة الإدارة (`/admin`)

- **الأسئلة الأكثر تكرارًا:** مجمّعة بالمعنى، فـ"كيف أنسحب؟" و"بدي أسحب مادة" سؤال واحد. تفيد الدائرة في كتابة إعلانات استباقية قبل فترات التسجيل.
- **أسئلة بلا جواب في الوثائق:** معلومات يحتاجها الطلبة وغير مكتوبة في أي وثيقة. هذه قيمة مباشرة للجامعة.
- **أكثر المواد اقتباسًا، والأسئلة يوميًا، ومتوسط التكلفة.**
- **رفع وثيقة جديدة** وإعادة بناء الفهرس فورًا.

## التكلفة

عبّئوا `PRICE_INPUT_PER_MTOK` و`PRICE_OUTPUT_PER_MTOK` من صفحة أسعار المزوّد، فتظهر تكلفة كل إجابة في الواجهة واللوحة وتقرير التقييم. كل سؤال = استدعاء صغير لإعادة الصياغة + استدعاء للإجابة. التكلفة الشهرية ≈ متوسط تكلفة الإجابة × عدد الطلبة × متوسط أسئلة الطالب شهريًا.

## الأمان والخصوصية

- المفاتيح في `.env` فقط ومستثناة في `.gitignore`.
- لوحة الإدارة والرفع محميان بـ `ADMIN_TOKEN`، والرمز يبقى في ذاكرة الصفحة ولا يُحفظ في المتصفح.
- السجل لا يحفظ هوية الطالب ولا عنوان IP، ويمكن إيقافه بـ `LOG_QUESTIONS=false`.
- الـ embeddings محلية، فالوثائق لا تُرسل لطرف ثالث إلا المقاطع المسترجعة عند التوليد.
- البرومبت يعامل محتوى الوثائق كبيانات لا أوامر (حماية من حقن التعليمات في وثيقة مرفوعة).
- الخطوة التالية للإنتاج: تسجيل دخول الطلبة بحساب الجامعة، وتحديد معدل الطلبات.

## التوسع

- **جامعات وبرامج أكثر:** ملف `courses.csv` لكل برنامج وحقل `program` للتصفية.
- **وثائق أكثر:** مخزن المتجهات NumPy يكفي حتى عشرات آلاف المقاطع، ثم يُستبدل بـ Qdrant أو pgvector داخل `rag/index.py` فقط.
- **قنوات أخرى:** الـ API جاهز لربطه ببوت واتساب أو تيليغرام.
